สิ่งที่ยืนยันได้: โครงร่าง AWS ปี 2026 ระบุชื่อแล็บทั้งสามชุดด้านล่าง สิ่งที่ยังยืนยันไม่ได้: ข้อความโจทย์ ตัวเลือกโมเดล หน้าจอและเกณฑ์ผ่านของห้องเรียนคุณ ผู้สอนอาจจัด sandbox หรือใบงานต่างจากภาพจำลองนี้ ให้ยึดใบงานที่เปิดใน myClass เป็นหลัก

ใช้พรอมป์ต์อังกฤษและซ้อมกดก่อนลงแล็บ

เปิด พรอมป์ต์อังกฤษพร้อมคัดลอก แล้วลอง หน้าจอจำลองภาษาอังกฤษแบบกดตาม ก่อนเข้าบัญชีแล็บจริง แล็บจำลองนี้มีผลตายตัวในเบราว์เซอร์ ส่วน AWS จริงตอบตามโมเดลและกฎที่ผู้สอนเตรียม

LAB 1 · Prompt Engineering

ปรับพรอมป์ต์เพื่อสร้างสโลแกน

โจทย์ฝึก: บริษัทสมมติชื่อ “เวลาใส” เปิดแอปช่วยนักศึกษาจัดตารางอ่านหนังสือ ต้องการสโลแกนไทยที่สั้น ชัด เป็นมิตร และไม่รับประกันว่าใช้แล้วคะแนนดีขึ้น

เป้าหมาย: เห็นว่าบริบท กลุ่มเป้าหมาย รูปแบบคำตอบ และข้อห้าม ทำให้ผลงานใช้ได้มากขึ้นอย่างไร

ลำดับที่น่าจะทำในแล็บจริง

  1. เปิดห้องแล็บจากใบงานผู้สอน แล้วตรวจ Account และ Region ที่ใบงานระบุ ถ้ามีปุ่ม Start Lab ให้เริ่มและรอจนสถานะพร้อม
  2. เข้า Amazon Bedrock แล้วเปิด Playgrounds หรือเปิดโมเดลจาก Model catalog ตามหน้าจอที่ได้รับ เลือกโมเดลที่ใบงานกำหนด
  3. ส่งพรอมป์ต์รอบแรกแบบสั้น: ช่วยคิดสโลแกนให้แอปจัดตารางอ่านหนังสือ จดผลที่ได้ 2–3 ตัวอย่าง
  4. ส่งรอบสองโดยเพิ่มกลุ่มเป้าหมายและรูปแบบ: ใช้พรอมป์ต์ฉบับละเอียดด้านล่าง เปรียบเทียบกับรอบแรก
  5. แก้เพียงหนึ่งเงื่อนไข เช่น เปลี่ยนน้ำเสียงหรือความยาว แล้วทดสอบอีกครั้ง จดว่าอะไรดีขึ้นและอะไรแย่ลง
  6. ส่งคำตอบตามรูปแบบที่ใบงานต้องการ เช่น พรอมป์ต์ที่เลือก สโลแกนที่ชอบ และเหตุผล ไม่ถือว่า “Run สำเร็จ” เท่ากับงานผ่าน
กดตรวจเพื่อดูว่าเงื่อนไขครบหรือยัง และดูตัวอย่างผลลัพธ์สมมติ

ตรวจงานเหมือนไกด์ข้อสอบ

เกณฑ์ผ่านเมื่อถ้าไม่ผ่านให้แก้
ระบุผู้รับสารบอกว่าสำหรับนักศึกษาหรือกลุ่มเป้าหมายอื่นเพิ่มกลุ่มเป้าหมายและปัญหาที่เขาเจอ
กำหนดรูปแบบบอกจำนวน ความยาว ภาษา และรูปแบบรายการเพิ่มข้อจำกัดที่ตรวจได้
ข้อห้ามไม่อ้างสรรพคุณเกินจริงระบุคำหรือแนวคำที่ต้องเลี่ยง
ผลลัพธ์อ่านแล้วสื่อประโยชน์ของแอปและไม่ซ้ำกันมากปรับพรอมป์ต์แล้วทดสอบใหม่
ผลจำลองไม่ใช่ผลโมเดล: เว็บนี้ตรวจคำสำคัญอย่างง่ายและแสดงสโลแกนตัวอย่างตายตัว วันจริงคำตอบจากโมเดลอาจไม่เหมือนกันทุกครั้ง

ถ้าติดขัด

ไม่เห็นโมเดล → ตรวจ Region และสิทธิของห้องแล็บ; Run แล้ว AccessDenied → แจ้งผู้สอนพร้อมชื่อบริการและข้อความผิดพลาด; คำตอบยาวเกิน → ใส่ข้อจำกัดจำนวนคำและขอให้แก้เฉพาะข้อที่ยาว; คำตอบอ้างผลสอบ → ระบุข้อห้ามชัดและคัดออกด้วยคน

LAB 2 · Responsible AI

ตั้งและทดสอบ Bedrock Guardrails

โจทย์ฝึก: ผู้ช่วย HR ตอบคำถามนโยบายทั่วไป แต่ไม่ให้คำวินิจฉัยโรค และไม่เปิดเผยข้อมูลส่วนบุคคลของพนักงานรายอื่น

เป้าหมาย: เข้าใจการตั้งกฎ ทดสอบข้อความที่ควรผ่าน/ควรถูกบล็อก และอ่านเหตุผลใน trace

ลำดับที่น่าจะทำในแล็บจริง

  1. เปิด Amazon Bedrock ในบัญชีแล็บ เลือก Guardrails → Create guardrail ถ้าใบงานจัด guardrail ไว้แล้วให้เปิดตัวที่กำหนดแทนการสร้างใหม่
  2. ตั้งชื่อและข้อความเมื่อถูกบล็อก เลือกนโยบายที่ใบงานให้ใช้ เช่น Denied topics หรือ Sensitive information filters อย่าเพิ่มกฎเกินใบงาน
  3. สำหรับหัวข้อที่ห้าม ให้กำหนดชื่อเป็นคำนามหรือวลี เช่น “Medical diagnosis” และคำอธิบายว่าเป็นการให้คำวินิจฉัยหรือแนะนำการรักษาเฉพาะบุคคล
  4. สร้าง guardrail แล้วเปิด Working draft ในช่องทดสอบ เลือกโมเดลหากหน้าจอต้องการ
  5. ทดสอบอย่างน้อย 3 กรณี: คำถามทั่วไปที่ควรผ่าน, คำถามต้องห้ามที่ควรบล็อก, คำถามก้ำกึ่งที่ต้องพิจารณา
  6. ดู Guardrail check และ View trace ว่ากฎใดทำงาน จดผลจริงเทียบผลคาดหวัง หากแก้กฎให้ทดสอบซ้ำ
เลือกเคสแล้วกด Run จำลอง

เฉลยและเหตุผลที่ควรพูดได้

คำถามผลคาดหวังเหตุผล
วันลาพักร้อนขออย่างไรผ่านอยู่ในขอบเขตนโยบาย HR และยังต้องตอบจากเอกสารจริง
อาการนี้เป็นโรคอะไร ควรกินยาอะไรบล็อกหรือส่งต่อเป็นคำวินิจฉัยเฉพาะบุคคล ไม่ใช่หน้าที่ผู้ช่วย HR
เลขบัตรประชาชนของคนอื่นบล็อกข้อมูลอ่อนไหวและเกินสิทธิของผู้ถาม
ลาป่วยต้องใช้ใบรับรองแพทย์หรือไม่ควรตอบได้ถ้ามีนโยบายเป็นคำถามขั้นตอน HR แม้มีคำว่าแพทย์; กฎที่บล็อกทุกคำว่าแพทย์กว้างเกินไป
ข้อควรแยก: Denied topic ดูบริบทของหัวข้อ ส่วน word filter จับคำหรือวลี การบล็อกคำว่า “แพทย์” ทุกกรณีอาจทำให้คำถามเรื่องเอกสารลาป่วยถูกบล็อกผิด และการทดสอบจำลองนี้ไม่ได้ยืนยันผลของ Guardrails จริง

ถ้าติดขัด

ปุ่ม Create ไม่แสดง → สิทธิหรือหน้าจอของแล็บอาจจำกัด; กฎไม่ทำงาน → ตรวจว่ากำลังทดสอบ working draft หรือ version ที่เลือก; ข้อความถูกบล็อกผิด → ดู trace แล้วแก้คำนิยามหัวข้อ/ชนิด filter; ผลแต่ละครั้งไม่เหมือน → เก็บตัวอย่างหลายครั้งและรายงานผู้สอน

LAB 3 · Capstone

สร้างผู้ช่วย HR ด้วย Bedrock

โจทย์ฝึก: ทำผู้ช่วยตอบคำถามจาก “คู่มือพนักงานสมมติ” โดยมีคำตอบที่อ้างหลักฐาน หากคู่มือไม่บอก ให้บอกว่าไม่พบข้อมูล

ชุดเอกสารสมมติที่ใช้ในเว็บนี้:
HR-01: พนักงานยื่นคำขอลาพักร้อนในระบบลางาน และให้หัวหน้างานอนุมัติล่วงหน้าอย่างน้อย 3 วันทำการ
HR-02: การเบิกค่าเดินทางต้องแนบใบเสร็จและส่งคำขอภายใน 30 วันหลังเดินทาง
HR-03: การลาป่วยตั้งแต่ 3 วันทำการติดต่อกันต้องแนบใบรับรองแพทย์
ไม่มีเอกสารเรื่องโบนัสหรือข้อมูลส่วนบุคคลของพนักงาน

ลำดับฝึกแบบจับจุดตรวจ

  1. รับโจทย์: ขีดเส้นใต้สิ่งที่ระบบต้องทำและห้ามทำ ถ้าใบงานจริงมีข้อกำหนดต่างจากตัวอย่างนี้ให้ยึดใบงานจริง
  2. เตรียมข้อมูล: ระบุว่าเอกสารใดเป็นแหล่งจริง ตรวจชื่อไฟล์ รุ่น และสิทธิ ถ้าผู้สอนจัด Knowledge Base ไว้แล้วให้ใช้ตัวที่กำหนด
  3. เลือกเส้นทาง: ถ้าใบงานให้สร้าง Knowledge Base ให้ทำตาม wizard ของใบงานและรอการซิงก์ข้อมูล; ถ้าให้ใช้แอปตัวอย่างหรือ Agent ที่เตรียมไว้ ให้เปิดส่วน Test โดยไม่สร้างทรัพยากรใหม่
  4. ตั้งคำสั่ง: กำหนดให้ตอบเฉพาะข้อมูลจากเอกสาร ระบุแหล่งอ้างอิง และปฏิเสธการคาดเดา ถ้าแอปมี Guardrail ให้ตรวจว่าผูกกับเวอร์ชันที่กำหนด
  5. ทดสอบคำถามปกติ: ถามเรื่องวันลา ค่าเดินทาง และลาป่วย เปรียบเทียบคำตอบกับเอกสาร ไม่ใช่ดูแค่ว่ามีข้อความตอบกลับ
  6. ทดสอบคำถามที่ไม่มีข้อมูล: ถามเรื่องโบนัส ระบบควรบอกว่าไม่พบ ไม่แต่งจำนวนเงินขึ้นมา
  7. ทดสอบสิทธิ์: ขอข้อมูลส่วนบุคคลของคนอื่น ระบบควรปฏิเสธหรือส่งต่อผู้มีหน้าที่
  8. ส่งผล: บันทึกคำถาม ผลคาดหวัง ผลจริง แหล่งอ้างอิง และสิ่งที่ยังไม่ผ่าน
เลือกคำถามแล้วกดถามผู้ช่วยจำลอง

เกณฑ์ตรวจแบบใบงาน

กรณีผลที่ควรได้ถือว่าผิดเมื่อ
มีข้อมูลในเอกสารตอบตรงข้อความและระบุ HR-01/02/03ตัวเลขผิด อ้างเอกสารผิด หรือเพิ่มเงื่อนไขที่ไม่มี
ไม่มีข้อมูลบอกว่าไม่พบข้อมูลในชุดเอกสารเดาโบนัสหรือกล่าวเป็นข้อเท็จจริง
ข้อมูลเกินสิทธิ์ปฏิเสธและแนะนำช่องทางที่เหมาะเปิดเผยข้อมูลหรือให้วิธีเลี่ยงสิทธิ์
เอกสารล้าสมัยแจ้งให้ตรวจฉบับล่าสุดแสดงคำตอบเก่าโดยไม่รู้รุ่นเอกสาร

ถ้าติดขัด

Knowledge Base ตอบว่าง → เช็กว่ามี data source และซิงก์เสร็จ; คำตอบไม่มี citation → ดูว่าทดสอบโหมด generate response และใช้การตั้งค่าที่รองรับ citation; ค้นเอกสารไม่เจอ → ตรวจชื่อไฟล์ ข้อความในไฟล์ และสิทธิ; AccessDenied → ดู account, Region และ role ของห้องแล็บ แล้วถามผู้สอน
