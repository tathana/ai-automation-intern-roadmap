Git/remote

Git เก็บประวัติ local บริการ Git เก็บ remote Commit ยังไม่ขึ้น remote จน push ใช้ repository ทีม ไม่ส่งโค้ดบริษัทไปบัญชีส่วนตัว

Workflow

README → status → branch ตามทีม → แก้ → diff → stage เฉพาะไฟล์ → diff --staged → commit → push ปลายทางที่ตรวจ ตาม review policy ไม่ใช้ force push เป็นจุดเริ่ม

Node/npm

Node รัน JavaScript npm จัด packages/scripts อ่าน package.json ก่อน install เพราะอาจรัน install scripts npm ci ต้อง lockfile ที่สอดคล้องและจัด node_modules ใหม่ ใช้ตาม README

Homebrew

ไม่ใช่สิ่งบังคับ หากอนุญาตใช้ทางการตาม IT Apple silicon default /opt/homebrew ไม่คัด PATH Intel ทับโดยไม่ตรวจ

Docker

ใช้ตัวติดตั้ง Apple silicon ตามนโยบายและสิทธิ์ใช้งานบริษัท Image อาจมีแต่ amd64 ต้องถามทีม ไม่เปิดทุกอย่างผ่าน Intel เพื่อแก้

ลดความซ้ำ

หลาย runtime/package manager ทำให้ PATH งง เริ่มจากชุดที่ทีมดูแลได้แล้วเพิ่มเมื่อมีเหตุผล

Git identity และการเข้าสู่ระบบ

ชื่อ/email ของ commit เป็น metadata ไม่ใช่รหัสผ่าน repository ตรวจ git config user.name และ git config user.email จากโปรเจกต์ ถ้าทีมกำหนดให้ตั้งรายโปรเจกต์ใช้ git config user.name "ชื่อที่ทีมกำหนด" และ git config user.email "เมลบริษัท" โดยไม่ใส่ --global ส่วนการเชื่อม remote ใช้ SSO/credential manager/SSH ตามทีม ไม่ใส่ token ใน URL

ตัวอย่าง · อ่านผลก่อนทำขั้นถัดไป

ป้าย “ไฟล์” ให้วางใน editor ส่วนป้าย “Terminal” พิมพ์ใน shell อ่านผลกระทบก่อนคัดลอก และรันทีละบรรทัดเมื่อยังไม่คุ้น

Terminal · อ่านข้อมูล

ดู Git

git status
git diff

ใน repository diff แสดง tracked ที่ยังไม่ stage ไฟล์ใหม่เปิดดูเอง

Terminal · อ่านข้อมูล

ตรวจ staged/remote

git diff --staged
git remote -v

ดูสิ่งที่จะ commit และปลายทาง fetch/push

Terminal · อ่านข้อมูล

ดู Node/npm

node --version
npm --version

เมื่อติดตั้งผ่านช่องทางทีมแล้ว

Terminal · อ่านรายการ

ดู scripts

npm run

จาก directory มี package.json ไม่ระบุชื่อ script เพื่อดูรายการ

Terminal · อ่านข้อมูล

หา Homebrew

command -v brew

ว่างไม่ได้แปลว่าจำเป็นต้องติดตั้ง
