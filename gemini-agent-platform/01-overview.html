บทที่ 1 — ภาพรวม Gemini Enterprise Agent Platform

เนื้อหาภาษาไทยแบบละเอียด เรียงตามเวลาในคลิป และสรุปท้ายเรื่อง จากข้อความถอดเสียงที่ผู้ใช้ส่งมา ตัดคำพูดซ้ำและคำอุทานออกเพื่อให้อ่านง่าย โดยคงสาระของผู้บรรยายไว้

ชื่อแพลตฟอร์มและรายละเอียดการเปิดตัวด้านล่างอ้างอิงตามคำบรรยายในคลิป ยังไม่ได้ตรวจสอบเทียบกับเอกสาร Google โดยตรง

เนื้อหาแบบละเอียด

0:00–0:50 — Gemini Enterprise Agent Platform คืออะไร

ผู้บรรยายแนะนำ Gemini Enterprise Agent Platform ซึ่งในคลิปเรียกย่อว่า GEAP และระบุว่า Google ประกาศเปิดตัวในงาน Google Cloud Next 2026

แพลตฟอร์มนี้อยู่บน Google Cloud และมีเป้าหมายเป็นชุดเครื่องมือที่ครอบคลุมการสร้าง AI Agent สำหรับองค์กร ตั้งแต่พัฒนา นำขึ้นใช้งาน ขยายระบบ ไปจนถึงดูแลและปรับปรุงประสิทธิภาพ

ประเด็นหลักคือ การสร้าง Agent ให้ทำงานได้บนเครื่องของนักพัฒนา กับการนำไปใช้งานจริงในองค์กร มีความต้องการต่างกันมาก

Agent ที่ทดลองบนเครื่องอาจทำงานได้ดี แต่เมื่อเริ่มนำไปใช้งานจริง จะต้องจัดการเรื่องเพิ่มเติม เช่น การรองรับผู้ใช้จำนวนมาก ความน่าเชื่อถือของระบบ การกำหนดสิทธิ์ และการติดตามปัญหา

ผู้บรรยายจึงเสนอให้มองแพลตฟอร์มนี้เป็นเครื่องมือสำหรับพา Agent จากขั้นทดลอง ไปสู่ระบบที่ใช้งานจริงในกระบวนการทำงานขององค์กรได้

0:51–1:20 — สี่ส่วนสำคัญของการพัฒนา Agent

ผู้บรรยายแบ่งกระบวนการออกเป็นสี่ส่วน:

ส่วน ความหมาย สิ่งที่ต้องจัดการ
Build สร้าง Agent โมเดล เฟรมเวิร์ก เครื่องมือ และทรัพยากรที่ Agent ใช้
Scale นำขึ้นใช้งานและขยายระบบ การ Deploy การเรียกใช้ ประวัติสนทนา และความจำ
Govern กำกับดูแล Agent ความปลอดภัย ตัวตน สิทธิ์ และนโยบายองค์กร
Optimize ประเมินและปรับปรุง การทดสอบ การติดตามการทำงาน และการวิเคราะห์ปัญหา

แนวคิดสำคัญคือ การพัฒนา Agent ไม่ได้จบเมื่อมันตอบคำถามหรือเรียกเครื่องมือได้ แต่ยังต้องทำให้ระบบรองรับการใช้งานจริง อยู่ภายใต้กฎขององค์กร และตรวจสอบคุณภาพได้ด้วย

1:21–2:12 — Build: สร้าง Agent

นักพัฒนา Agent มักคุ้นเคยกับส่วนนี้มากที่สุด เพราะเป็นขั้นที่เลือกโมเดล เขียนพฤติกรรม และเชื่อมต่อเครื่องมือต่าง ๆ

เฟรมเวิร์กที่ผู้บรรยายยกตัวอย่าง ได้แก่:

  • Google Agent Development Kit หรือ ADK
  • LangChain
  • LangGraph

ในมุมที่ผู้บรรยายอธิบาย ตัวโมเดลภาษาหรือ LLM เป็นแกนหลักของ Agent แต่หากใช้งานโมเดลเพียงอย่างเดียว ก็จะมีลักษณะรับข้อมูลเข้าแล้วสร้างคำตอบกลับมา

การสร้าง Agent จึงต้องนำโมเดลมาทำงานร่วมกับเฟรมเวิร์ก และเชื่อมต่อเครื่องมือหรือทรัพยากรภายนอก เพื่อให้ระบบทำงานที่ต้องการได้

เมื่อสร้าง Agent ให้ทำงานบนเครื่องของตนเองได้แล้ว ขั้นต่อไปคือการนำระบบนั้นขึ้นไปใช้งานบนคลาวด์

2:13–3:03 — Scale: Deploy ระบบ จัดการ Session และเพิ่ม Memory

ส่วน Scale ครอบคลุมงานหลักสามอย่าง:

  1. นำ Agent ขึ้นใช้งาน หรือ Deploy
  2. จัดการ Agent ที่ Deploy แล้ว
  3. เรียกใช้งานผ่าน API หรือ SDK

นอกจากการรัน Agent แล้ว ยังต้องดูแลข้อมูลจากการใช้งานด้วย โดยผู้บรรยายเน้นสองเรื่องคือ Sessions และ Memory Bank

Sessions — ประวัติการสนทนา

เมื่อผู้ใช้โต้ตอบกับ Agent ระบบต้องจัดการประวัติและบริบทของการสนทนา เพื่อให้ติดตามได้ว่าในการสนทนานั้นมีอะไรเกิดขึ้นบ้าง

Memory Bank — ความจำระยะยาว

Agent อาจต้องจำข้อมูลบางอย่างเกี่ยวกับผู้ใช้ เพื่อนำมาปรับการตอบสนองในการสนทนาครั้งต่อไปให้เหมาะกับผู้ใช้คนนั้น

Sessions Memory Bank
จัดการประวัติและบริบทของการสนทนา เก็บข้อมูลบางอย่างเพื่อใช้ข้ามการสนทนา
ช่วยติดตามสิ่งที่เกิดขึ้นในแต่ละ Session ช่วยให้ Agent ใช้ข้อมูลเดิมในการสนทนาครั้งใหม่

เมื่อสร้าง Agent และนำขึ้นใช้งานเรียบร้อย ก็ถือว่าผ่านส่วน Build และ Scale แล้ว จากนั้นจึงเข้าสู่การกำกับดูแล

3:04–3:43 — Govern: ความปลอดภัย ตัวตน และสิทธิ์

ผู้บรรยายกล่าวถึงการกำกับดูแลสามด้าน

1. ความปลอดภัยของเนื้อหา

ระบบต้องตรวจสอบและกรองทั้งข้อความที่ส่งเข้า Agent และข้อความที่ Agent ส่งออก เพื่อให้เป็นไปตามข้อกำหนดด้านความปลอดภัย เครื่องมือที่กล่าวถึงคือ Model Armor

2. ตัวตนและสิทธิ์ของ Agent

องค์กรต้องกำหนดว่า Agent มีตัวตนอย่างไร และได้รับอนุญาตให้เข้าถึงหรือดำเนินการอะไรได้บ้าง

ผู้บรรยายกล่าวถึง Agent Identity และ Google Cloud IAM — Identity and Access Management สำหรับจัดการตัวตน สิทธิ์ และการควบคุมการเข้าถึง

3. การแบ่งปัน Agent ภายในองค์กร

เมื่อสร้าง Agent แล้ว อาจต้องเปิดให้คนอื่นในองค์กรใช้งานร่วมกัน ซึ่งเป็นอีกความสามารถที่ผู้บรรยายระบุว่าแพลตฟอร์มรองรับ

3:44–5:23 — Optimize: ประเมินคุณภาพและติดตามการทำงาน

หลังจากสร้าง Deploy และกำหนดนโยบายแล้ว ต้องตรวจสอบว่า Agent ทำงานได้ตามที่คาดหรือไม่ และจะปรับปรุงอย่างไร ผู้บรรยายแบ่งเรื่องนี้เป็นการประเมิน Agent และการติดตามการทำงาน

การประเมินด้วยชุดทดสอบที่กำหนดความคาดหวังไว้

สร้างชุดประเมิน หรือ Evaluation Set โดยระบุข้อมูลนำเข้าและพฤติกรรมที่คาดหวัง สิ่งที่ตรวจสอบอาจเป็น:

  • Agent ให้ผลลัพธ์ตามที่ต้องการหรือไม่
  • เรียกเครื่องมือที่ควรเรียกหรือไม่
  • เข้าถึงหรือเขียนข้อมูลตามที่กำหนดหรือไม่

วิธีนี้เหมาะกับงานที่สามารถตั้งเกณฑ์ตรวจสอบได้ชัดเจน ผู้บรรยายกล่าวว่าจะใช้ความสามารถด้านการประเมินของ ADK มาช่วย

คำว่า Deterministic Evaluation ในบริบทนี้หมายถึงการตรวจตามเกณฑ์ที่กำหนดชัดเจน ไม่ได้หมายความว่า Agent จะสร้างคำตอบเหมือนเดิมทุกครั้งโดยอัตโนมัติ

การใช้ LLM อีกตัวประเมิน — LLM as a Judge

บางงานไม่สามารถตัดสินคุณภาพด้วยกฎตายตัวได้สะดวก จึงใช้โมเดลภาษาอีกตัวช่วยประเมินคำตอบของ Agent ผู้บรรยายระบุว่าจะสอนทั้งการประเมินด้วยเกณฑ์ที่กำหนดไว้ และการใช้ LLM เป็นผู้ประเมิน

Observability และ Traces

เพื่อประเมินและแก้ปัญหา ต้องมีข้อมูลที่บอกว่า Agent ทำอะไรไปบ้างระหว่างทำงาน ผู้บรรยายกล่าวถึงการใช้ OpenTelemetry เพื่อเก็บเหตุการณ์และข้อมูล เช่น:

  • จำนวน Token ที่ใช้
  • Prompt ที่เกี่ยวข้องกับการทำงาน
  • ลำดับขั้นตอนที่ Agent ดำเนินการ
  • ข้อมูลประกอบการวิเคราะห์พฤติกรรมของระบบ

Trace ช่วยให้เห็นเส้นทางการทำงานของ Agent ว่าผ่านขั้นตอนใดมาบ้าง จึงมีประโยชน์ต่อการตรวจสอบงานที่ซับซ้อนและการหาจุดที่เกิดปัญหา

การติดตามลักษณะนี้หมายถึงการดูขั้นตอนและข้อมูลที่ระบบบันทึกได้ ไม่ควรตีความว่าเห็นกระบวนการคิดภายในทั้งหมดของโมเดล

เมื่อรวมทุกส่วนเข้าด้วยกัน เป้าหมายคือได้ Agent ที่สร้างได้ ขยายระบบได้ อยู่ภายใต้นโยบายที่กำหนด และมีข้อมูลเพียงพอสำหรับประเมินและปรับปรุง

5:24–6:17 — โครงสร้างคอร์ส: เตรียมสภาพแวดล้อม

ช่วงนี้ผู้บรรยายเปลี่ยนจากการอธิบายภาพรวม มาเป็นการแจกแจงสิ่งที่จะเรียนในคอร์ส ขั้นแรกคือเตรียมเครื่องมือ ได้แก่:

  • เครื่องมือ CLI สำหรับ Agent ตามที่กล่าวในคลิป
  • uv สำหรับจัดการแพ็กเกจ
  • Visual Studio Code หรือ IDE อื่นที่ผู้เรียนถนัด
  • Python สำหรับรัน Agent

จากนั้นจะตั้งค่าการยืนยันตัวตนกับ Google Cloud โดยใช้ Application Default Credentials หรือ ADC และตั้งค่า Google Cloud พร้อมเปิด API ที่จำเป็นต่อการใช้งานแพลตฟอร์ม

คลิปนี้เป็นเพียงการบอกหัวข้อที่จะเรียน ยังไม่ได้แสดงคำสั่งติดตั้งหรือขั้นตอนตั้งค่าจริง

6:18–6:47 — ส่วน Build ของคอร์ส

ผู้เรียนจะสร้าง Agent บนเครื่องของตนเองด้วย ADK โดย:

  1. ใช้โมเดล Gemini
  2. เพิ่มเครื่องมือให้ Agent เรียกใช้งาน
  3. ทำให้ Agent ทำงานในสภาพแวดล้อม Local ได้

ผู้บรรยายชี้แจงว่า คอร์สจะเน้นการใช้แพลตฟอร์มเพื่อนำ Agent ไปใช้งาน ขยายระบบ กำกับดูแล และปรับปรุง มากกว่าการลงรายละเอียดทุกส่วนของ ADK

6:48–7:15 — ส่วน Scale ของคอร์ส

หัวข้อที่จะเรียน ได้แก่:

  • Deploy Agent ด้วย Agent Runtime
  • ใช้ Agent Console และ Playground บน Google Cloud
  • จัดการ Agent Sessions
  • ใช้ Memory Bank

Sessions จะช่วยติดตามบทสนทนา ส่วน Memory Bank จะช่วยเก็บข้อมูลบางอย่างจากการสนทนาเพื่อนำกลับมาใช้ข้าม Session

7:16–7:55 — ส่วน Govern ของคอร์ส

ผู้เรียนจะดูวิธีกำหนดตัวตนให้ Agent และจัดการสิทธิ์ผ่าน IAM

ผู้บรรยายระบุว่าจะกล่าวถึงทั้งแนวทางใช้ Agent Identity และการจัดการผ่าน IAM ในกรณีที่ไม่ได้ใช้ Agent Identity โดยรายละเอียดวิธีทำยังไม่ได้แสดงในคลิปนี้

อีกหัวข้อคือการใช้ Model Armor ตรวจข้อความเข้าและข้อความออก เพื่อช่วยควบคุมเนื้อหาที่องค์กรไม่ยอมรับ

7:56–8:57 — ส่วน Optimize ของคอร์ส

ส่วนนี้จะสอนสองเรื่องหลัก

ติดตามการทำงาน — ใช้ Observability และ Traces เพื่อดูข้อมูลด้านประสิทธิภาพและขั้นตอนการทำงาน แล้วนำข้อมูลเหล่านั้นมาปรับปรุง Agent

ประเมินผล — ใช้ทั้งชุดทดสอบที่ระบุ Input และผลลัพธ์หรือ Tool Call ที่คาดหวัง และ LLM อีกตัวช่วยประเมินงานที่ตรวจด้วยกฎตายตัวได้ยาก ผู้บรรยายจะนำทั้งสองวิธีมาใช้กับตัวอย่างของคอร์ส

8:58–9:42 — โครงงานปลายคอร์ส

ผลงานที่สร้างตลอดคอร์สจะรวมเป็น Course Project ซึ่งครอบคลุมทั้ง Build, Scale, Govern และ Optimize

ผู้เรียนสามารถเลือกแอปพลิเคชันที่สนใจ หรือทำตามตัวอย่างที่ผู้สอนเลือก แล้วพัฒนาจนเป็นโครงงานที่สมบูรณ์

ผู้บรรยายเสนอว่าสามารถนำผลงานนี้ไปแสดงให้เพื่อน เพื่อนร่วมงาน หรือผู้สรรหาบุคลากรดู เพื่อแสดงทักษะการพัฒนา Agent บทถัดไปจะเริ่มลงมือเตรียมสภาพแวดล้อมและตั้งค่าพื้นฐาน

สรุปท้ายเรื่อง

คลิปนี้เป็น บทนำและแผนการเรียน ของคอร์สพัฒนา Agent สำหรับองค์กร ยังไม่มีการสาธิตเขียนโค้ดหรือ Deploy จริง

สาระสำคัญคือ การมี Agent ที่ทำงานบนเครื่องได้ เป็นเพียงจุดเริ่มต้น การใช้งานระดับองค์กรยังต้องจัดการอีกหลายด้าน:

ขั้น สิ่งที่จะทำ เครื่องมือหรือแนวคิดที่กล่าวถึง
Build สร้าง Agent และเชื่อมเครื่องมือ ADK, Gemini, Tools
Scale นำขึ้นคลาวด์และจัดการการใช้งาน Agent Runtime, API/SDK, Sessions, Memory Bank
Govern ควบคุมตัวตน สิทธิ์ และเนื้อหา Agent Identity, IAM, Model Armor
Optimize ตรวจคุณภาพและหาจุดปรับปรุง Evaluation Sets, LLM as a Judge, OpenTelemetry, Traces

สิ่งที่ควรจำจากคลิปมีสามข้อ:

  1. Session กับ Memory ทำหน้าที่ต่างกัน — Session ดูแลประวัติการสนทนา ส่วน Memory เก็บข้อมูลเพื่อนำไปใช้ในการสนทนาครั้งต่อไป
  2. การประเมินต้องดูทั้งคำตอบและการกระทำ — Agent อาจต้องเรียกเครื่องมือหรือเขียนข้อมูลให้ถูกต้องด้วย
  3. ต้องติดตามขั้นตอนการทำงานได้ — การเห็นเพียงคำตอบสุดท้ายอาจไม่เพียงพอสำหรับหาสาเหตุเมื่อระบบผิดพลาด

เป้าหมายของคอร์สคือให้ผู้เรียนมีโครงงาน Agent ที่ผ่านครบทั้งสี่ด้าน และนำไปใช้แสดงทักษะได้
