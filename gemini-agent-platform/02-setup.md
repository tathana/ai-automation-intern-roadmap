# บทที่ 2 — เตรียมเครื่องและสร้าง Agent ตัวแรก

บทนี้เป็น **การเตรียมเครื่องและ Google Cloud จนสามารถรัน Agent ตัวแรกผ่านหน้าเว็บบนเครื่องของตนเองได้** ความยาวประมาณ 25 นาที

เนื้อหาด้านล่างเรียงตามเวลา ตัดคำซ้ำและอธิบายศัพท์ที่จำเป็น พร้อมสรุปท้ายเรื่อง ข้อความถอดเสียงมีชื่อคำสั่งและชื่อโมเดลบางจุดที่อาจคลาดเคลื่อน จึงแยกจุดเหล่านั้นไว้เพื่อไม่ให้นำไปใช้ผิด

## เนื้อหาแบบละเอียด

### 0:00–3:52 — ภาพรวมการตั้งค่า 6 ขั้นตอน

ต่อจากบทก่อนที่แนะนำแพลตฟอร์ม บทนี้จะลงมือเตรียมสภาพแวดล้อมสำหรับสร้าง Agent ผู้บรรยายเสนอให้ทำตามลำดับหกขั้นตอน เพื่อลดปัญหาจากการตั้งค่าไม่ครบและการต้องย้อนกลับมาแก้หลายรอบ

| ขั้นตอน | สิ่งที่จะทำ | ผลลัพธ์ที่ต้องการ |
| --- | --- | --- |
| 1. เตรียมเครื่องพัฒนา | ติดตั้ง Python, Git, VS Code, uv, Node.js และ Agents CLI | เครื่องพร้อมสร้างและรันโปรเจกต์ |
| 2. เตรียม Google Cloud | สร้างบัญชีและ Project พร้อมเปิด API ที่จำเป็น | มี Project ID สำหรับใช้งาน |
| 3. สร้าง Agent | ใช้ CLI สร้างโครงโปรเจกต์ | ได้ไฟล์ Agent และไฟล์ตั้งค่า |
| 4. ยืนยันตัวตน | ตั้งค่า Application Default Credentials | โปรแกรมบนเครื่องเรียก Google Cloud ได้ตามสิทธิ์ |
| 5. ตั้งค่า Agent | ใส่ Project ID และค่าการเชื่อมต่อใน `.env` | Agent รู้ว่าจะใช้บริการผ่านโปรเจกต์ใด |
| 6. รันและทดสอบ | เปิด Playground แล้วส่งข้อความ | ทดสอบการตอบและการเรียกเครื่องมือได้ |

ไฟล์ที่ผู้บรรยายให้ความสำคัญในช่วงเริ่มต้นมีสองไฟล์:

- **`agent.py`** — นิยาม Agent โมเดล คำสั่ง และเครื่องมือ
- **`.env`** — เก็บค่าตั้งค่าสภาพแวดล้อม เช่น Google Cloud Project ID

Agent ที่สร้างจะใช้ **ADK หรือ Agent Development Kit** ซึ่งเป็นเฟรมเวิร์กโอเพนซอร์สของ Google สำหรับพัฒนา Agent

ภาพการทำงานเมื่อทดสอบสำเร็จคือ:

**ผู้ใช้ส่งข้อความในหน้าเว็บ → Root Agent รับข้อความ → เรียกโมเดล Gemini → เรียกเครื่องมือเมื่อจำเป็น → ส่งคำตอบกลับ**

ผู้บรรยายเชื่อมโยงว่า การเริ่มด้วยโครงสร้างนี้จะช่วยให้ต่อยอดไปสู่การ Deploy การกำกับดูแล และการติดตามประสิทธิภาพในบทถัดไปได้

### 3:53–4:59 — ติดตั้งเครื่องมือพื้นฐาน

ผู้บรรยายแนะนำให้ติดตั้งเครื่องมือดังต่อไปนี้

| เครื่องมือ | หน้าที่ |
| --- | --- |
| **Python** | ภาษาที่ใช้เขียนและรัน Agent ในคอร์ส |
| **Git** | จัดการเวอร์ชันของโค้ดและทำงานกับ Repository |

### 5:00–5:47 — สร้าง Google Cloud Project

เริ่มจากใช้บัญชี Google เข้า Google Cloud Console แล้วสร้างโปรเจกต์สำหรับงานนี้

ค่าที่ต้องเก็บไว้คือ **Project ID** เพราะจะใช้ทั้งในคำสั่งของ Google Cloud และไฟล์ตั้งค่าของ Agent ต้องแยกให้ชัดว่า:

- **Project name** คือชื่อที่แสดงให้คนอ่าน
- **Project ID** คือรหัสโปรเจกต์ที่ใช้ในการตั้งค่าและคำสั่งต่าง ๆ
- **Project number** คือหมายเลขอีกชนิดหนึ่งของโปรเจกต์

ในบทนี้ ผู้บรรยายต้องการให้ใช้ **Project ID**

ผู้บรรยายกล่าวถึงเครดิตฟรีเริ่มต้นจำนวน 300 ดอลลาร์สำหรับผู้ใช้ใหม่ แต่สิทธิ์จริงและเงื่อนไขการใช้ต้องตรวจสอบจากบัญชีและข้อเสนอของ Google ในขณะสมัคร ไม่ควรถือว่าทุกบัญชีจะได้รับเหมือนกัน

### 5:48–7:58 — ติดตั้ง Agents CLI

ผู้บรรยายเปิดหน้า GitHub ของเครื่องมือที่เรียกว่า **Agents CLI** และอธิบายว่าเป็นเครื่องมือบรรทัดคำสั่งสำหรับสร้างและ Deploy Agent บนแพลตฟอร์ม

สิ่งที่ต้องเตรียมก่อนติดตั้งตามคลิป ได้แก่ Python, uv และ Node.js

จากนั้นคัดลอกคำสั่งที่ใช้ `uvx` จากหน้า Repository มารันใน Terminal ระบบจะเตรียมส่วนประกอบที่เครื่องมือต้องใช้ และรายงานผลการติดตั้ง CLI กับ Skills

**ในข้อความถอดเสียงไม่มีคำสั่งติดตั้งแบบเต็มหรือ URL ของ Repository** จึงยังไม่สามารถนำส่วนนี้ไปเขียนเป็นคำสั่งติดตั้งที่ยืนยันความถูกต้องได้

ช่วงท้าย ผู้บรรยายทบทวนว่าเตรียมเครื่องมือพัฒนาบนเครื่อง Google Cloud Project, Google Cloud CLI หรือ `gcloud` และ Agents CLI แล้ว

เครื่องมือ CLI สองตัวนี้มีบทบาทต่างกัน:

| เครื่องมือ | ใช้ทำอะไรในบทนี้ |
| --- | --- |
| **Google Cloud CLI — `gcloud`** | ยืนยันตัวตน เลือก Project และเปิด API |
| **Agents CLI** | สร้างโครง Agent และเปิด Playground |

ผู้บรรยายระบุว่าจะเปิด API เพิ่มเติมเมื่อจำเป็นระหว่างทำโปรเจกต์ อย่างไรก็ตาม หากเกิดข้อผิดพลาด สาเหตุอาจมาจากเรื่องอื่นด้วย เช่น สิทธิ์ บัญชี การตั้งค่า Project หรือ Billing จึงต้องอ่านรายละเอียดข้อผิดพลาดประกอบ

### 7:59–10:09 — สร้าง Agent ตัวแรก

ผู้บรรยายเริ่มจากสร้างโฟลเดอร์สำหรับงานพัฒนา แล้วสร้างโฟลเดอร์โปรเจกต์ชื่อประมาณ `GAP_v1`

จากนั้นใช้ Agents CLI ตรวจสอบเวอร์ชัน และเรียกคำสั่งสร้างโปรเจกต์ โดยตั้งชื่อ Agent ว่า **Website Generator**

สิ่งที่ CLI สร้างให้เรียกว่า **Scaffold** หมายถึงโครงโปรเจกต์เริ่มต้น ซึ่งมีไฟล์และโฟลเดอร์พื้นฐานพร้อมให้แก้ไขต่อ

ในการสาธิต คำสั่งครั้งแรกพบปัญหา ผู้บรรยายจึงเพิ่มแฟล็ก **`-y`** เพื่อให้ทำงานแบบไม่ถามตอบและใช้ค่าเริ่มต้น ตามพฤติกรรมของ CLI ที่แสดงในคลิป

ค่าที่เลือกในตัวอย่าง ได้แก่:

- ใช้ **ADK** เป็นเฟรมเวิร์ก
- ใช้ **Agent Runtime** เป็นเป้าหมายการ Deploy
- ข้ามการตั้งค่า **CI/CD Runner** ในตอนนี้

ระบบยังตรวจข้อมูลรับรองของ Google Cloud และพบข้อผิดพลาดลักษณะ:

> Permission denied … project none

ในบริบทของตัวอย่าง ผู้บรรยายอธิบายว่า ยังไม่ได้ตั้งค่าโปรเจกต์และข้อมูลรับรองให้ครบ

จากนั้นเปิดโฟลเดอร์ปัจจุบันใน VS Code ด้วย:

```bash
code .
```

**แม้ตั้งชื่อว่า Website Generator แต่ในบทนี้ Agent ยังใช้พฤติกรรมและเครื่องมือเริ่มต้น ไม่ได้สร้างเว็บไซต์จริงแล้ว**

### 10:10–12:17 — ทำความเข้าใจ `app/agent.py`

ภายในโปรเจกต์ที่สร้าง มีโฟลเดอร์ `app` และไฟล์สำคัญคือ:

```text
app/agent.py
```

ผู้บรรยายเรียกไฟล์นี้ว่า **Agent Definition Module** หรือไฟล์นิยาม Agent องค์ประกอบสำคัญของไฟล์ ได้แก่:

1. การ Import ส่วนประกอบที่ใช้
2. การระบุโมเดล
3. ฟังก์ชันเครื่องมือ
4. การสร้าง Root Agent
5. การห่อ Agent ไว้ใน Application

ผู้บรรยายอธิบายว่า การมีโมเดลภาษาอย่างเดียวไม่ได้ทำให้โปรแกรมเชื่อมข้อมูลสด มีความจำระยะยาว หรือดำเนินการภายนอกได้โดยอัตโนมัติ ต้องมีการเชื่อมส่วนประกอบเหล่านั้นผ่านระบบ Agent

ในข้อความถอดเสียงมีการยกชื่อโมเดลหลายชื่อ แต่ยังยืนยันไม่ได้ว่าเป็นชื่อจริงตามหน้าจอหรือเป็นความคลาดเคลื่อนของการถอดเสียง หากจะลงมือทำ ต้องใช้ **Model ID ที่รองรับจริงในบริการและตำแหน่งที่เลือก**

### 12:18–14:55 — Root Agent ประกอบด้วยอะไรบ้าง

ผู้บรรยายใช้คลาส `Agent` จาก ADK เพื่อสร้าง Agent หลัก โดยอ้างถึงตัวแปร **`root_agent`** เป็นจุดเริ่มต้นที่รับข้อความจากผู้ใช้ แล้วเริ่มกระบวนการทำงาน

**1. Name — ชื่อ Agent**

ใช้ระบุ Agent ในระบบและข้อมูลติดตามการทำงาน ผู้บรรยายกล่าวถึงการใช้งานชื่อใน Logs, Telemetry และบริบทการสื่อสารระหว่าง Agent

คำว่า **A2A — Agent-to-Agent** หมายถึงโปรโตคอลสำหรับการสื่อสารระหว่าง Agent แต่บทนี้ยังไม่ได้สาธิตการใช้งานจริง

**2. Model — โมเดลที่ใช้**

กำหนดว่า Agent จะใช้โมเดลใดในการประมวลผล ตัวอย่างยังมีการกำหนดตัวเลือก Retry โดยตั้งค่าจำนวน Attempts เป็น 3 เพื่อรองรับกรณีอย่างปัญหาเครือข่ายหรือ Rate Limit ทั้งนี้ ความหมายว่าจำนวนนี้นับรวมครั้งแรกหรือไม่ต้องดูข้อกำหนดของไลบรารีที่ใช้

**3. Instructions — คำสั่งหลัก**

เป็นคำสั่งสำหรับกำหนดบทบาทและพฤติกรรม เช่น Agent ทำหน้าที่อะไร ควรตอบด้วยน้ำเสียงแบบใด และมีขอบเขตการทำงานอย่างไร

คำสั่งเริ่มต้นในตัวอย่างมีสาระประมาณว่า:

> คุณเป็นผู้ช่วย AI ที่ให้ข้อมูลถูกต้องและเป็นประโยชน์

ในขั้นนี้ยังไม่ได้ปรับคำสั่งให้ทำหน้าที่สร้างเว็บไซต์โดยเฉพาะ

**4. Tools — เครื่องมือที่ Agent เรียกได้**

เป็นรายการฟังก์ชัน Python ที่อนุญาตให้ Agent ใช้งาน ตัวอย่างมีเครื่องมือดูสภาพอากาศและเครื่องมือดูเวลาปัจจุบัน

ADK จะใช้ข้อมูลเกี่ยวกับฟังก์ชันเพื่ออธิบายให้โมเดลทราบว่าเครื่องมือทำอะไรและควรเรียกอย่างไร

### 14:56–16:45 — ทำไมคำอธิบายฟังก์ชันและ Type Hints จึงสำคัญ

ผู้บรรยายเน้นว่า **Docstring และ Type Hints มีผลต่อการใช้เครื่องมือของ Agent**

- **Docstring** คือข้อความอธิบายว่าฟังก์ชันทำอะไร รับค่าอะไร และคืนค่าอะไร
- **Type Hints** คือการระบุชนิดข้อมูล เช่น พารามิเตอร์เป็นข้อความ

ADK ใช้ข้อมูลเหล่านี้ในการสร้างคำอธิบายหรือ Schema ของเครื่องมือให้โมเดลเข้าใจ โมเดลจึงใช้ข้อมูลดังกล่าวช่วยตัดสินใจว่า:

1. เมื่อใดควรเรียกเครื่องมือนี้
2. ต้องส่งอาร์กิวเมนต์อะไร
3. จะได้รับข้อมูลประเภทใดกลับมา

ผลในทางปฏิบัติคือ ถ้าอธิบายเครื่องมือไม่ชัด Agent ก็อาจเลือกใช้ผิดหรือส่งข้อมูลไม่ตรงกับที่ฟังก์ชันต้องการ

**เครื่องมือสภาพอากาศในตัวอย่างเป็นข้อมูลจำลอง**

ฟังก์ชันตรวจว่าข้อความมีคำว่า `SF` หรือ `San Francisco` หรือไม่ หากพบ จะคืนข้อมูลที่กำหนดไว้ล่วงหน้าว่าอุณหภูมิ 60 องศาฟาเรนไฮต์ และมีหมอก หากเป็นสถานที่อื่น จะคืนคำตอบจำลองอีกแบบหนึ่ง

ดังนั้น ตัวอย่างนี้ใช้สาธิตว่า Agent เรียกเครื่องมือได้ ไม่ได้ยืนยันว่ามันเชื่อมบริการพยากรณ์อากาศจริง

ส่วนเครื่องมือดูเวลาปัจจุบัน ผู้บรรยายให้ผู้เรียนศึกษาจากโค้ดและคำอธิบายเพิ่มเติมด้วยตนเอง ผู้บรรยายยังบอกว่า คอมเมนต์ละเอียดในไฟล์เป็นสิ่งที่เพิ่มภายหลังโดยใช้ Gemini ช่วยอธิบาย ไม่ใช่ทั้งหมดที่ CLI สร้างให้อัตโนมัติ

### 16:46–17:35 — ห่อ Agent เป็น Application

องค์ประกอบสุดท้ายคือ **Application ระดับบนของ ADK** หน้าที่คือรวมการตั้งค่า Agent ไว้ในโครงสร้างแอปพลิเคชันที่ระบบนำไปใช้งานต่อได้ และเชื่อม Root Agent เข้ากับชื่อแอป

ในตัวอย่างใช้ชื่อแอปว่า **`app`** ซึ่งจะปรากฏในส่วนต่าง ๆ ของระบบ เช่น หน้า Playground หรือเส้นทาง API ตามโครงสร้างที่ใช้งาน

```text
Application
└── Root Agent
    ├── Model
    ├── Instructions
    └── Tools
```

จุดนี้เป็นการเตรียมโครงสร้างแอป ยังไม่ได้แสดงว่า Deploy ขึ้นคลาวด์สำเร็จแล้ว

### 17:36–19:22 — ยืนยันตัวตนด้วย Application Default Credentials

ก่อนเรียกโมเดลผ่าน Google Cloud ต้องให้โปรแกรมบนเครื่องมีข้อมูลรับรองสำหรับเข้าถึงบริการ ผู้บรรยายใช้ **Application Default Credentials หรือ ADC** ด้วยคำสั่ง:

```bash
gcloud auth application-default login
```

คำสั่งนี้จะเปิดเบราว์เซอร์ให้เลือกบัญชี Google และทำขั้นตอนอนุญาตการเข้าถึง ควรเลือกบัญชีที่มีสิทธิ์ใช้งาน Google Cloud Project ที่เตรียมไว้ เมื่อทำเสร็จ ไลบรารีที่รองรับ ADC จะสามารถใช้ข้อมูลรับรองนี้เรียกบริการตามสิทธิ์ของบัญชีได้

สิ่งที่ต้องแยกให้ชัดคือ:

- **การยืนยันตัวตน** บอกว่าโปรแกรมทำงานในนามใคร
- **สิทธิ์ IAM** บอกว่าตัวตนนั้นทำอะไรได้
- **Project และ Billing** กำหนดบริบททรัพยากร โควตา และค่าใช้จ่ายตามบริการ

การ Login เพียงอย่างเดียวจึงไม่ได้ทำให้มีสิทธิ์ใช้ทุกบริการโดยอัตโนมัติ

นอกจากนี้ ADC กับการ Login สำหรับตัว `gcloud` เป็นการตั้งค่าที่แยกกันได้ หากคำสั่ง CLI ยังแจ้งว่าไม่ได้ Login ก็ต้องตรวจบัญชีของ CLI เพิ่มเติม

### 19:23–20:51 — เลือก Project สำหรับโควตาและทำความเข้าใจค่าใช้จ่าย

หากยังไม่ทราบ Project ID ผู้บรรยายใช้:

```bash
gcloud projects list
```

ผลลัพธ์จะแสดงข้อมูลของโปรเจกต์ เช่น Project ID ชื่อ และ Project number โดยต้องนำ **Project ID** มาใช้ จากนั้นตั้งค่า Quota Project สำหรับ ADC:

```bash
gcloud auth application-default set-quota-project YOUR_PROJECT_ID
```

แทน `YOUR_PROJECT_ID` ด้วยรหัสโปรเจกต์จริง

**Quota Project** เป็นโปรเจกต์ที่ใช้ประกอบการคิดโควตาและค่าใช้จ่ายสำหรับคำขอบางประเภทที่ใช้ข้อมูลรับรองนั้น โดยรายละเอียดขึ้นกับบริการ ไม่ได้ย้ายค่าใช้จ่ายของทรัพยากรทุกชนิดไปโปรเจกต์นี้ทั้งหมด

ผู้บรรยายย้ำว่า การเรียกโมเดลและ API อาจมีค่าใช้จ่าย และเครดิตฟรีบางประเภทอาจมีข้อจำกัดด้านบริการที่ใช้ได้ ข้อแนะนำคือทดลองเรียก Agent จำนวนเล็กน้อย แล้วตรวจสอบ Billing ว่ามีค่าใช้จ่ายรายการใดเกิดขึ้น และเครดิตถูกนำมาหักกับรายการนั้นหรือไม่

### 20:52–21:48 — เลือก Project ใน CLI และเปิด API

ตั้งค่า Project เริ่มต้นของ `gcloud`:

```bash
gcloud config set project YOUR_PROJECT_ID
```

คำสั่งนี้กับการตั้ง Quota Project ก่อนหน้ามีหน้าที่ต่างกัน:

| คำสั่ง | หน้าที่ |
| --- | --- |
| `gcloud config set project ...` | กำหนด Project เริ่มต้นสำหรับคำสั่ง `gcloud` |
| `gcloud auth application-default set-quota-project ...` | กำหนด Quota Project สำหรับ ADC |

จากนั้นผู้บรรยายเปิด API ที่เรียกว่า **Agent Platform API** และระบุว่าอาจใช้เวลาสักครู่ก่อนพร้อมใช้งาน

**จุดที่ต้องตรวจสอบก่อนทำตาม:** ข้อความถอดเสียงระบุชื่อบริการว่า `platform.googleapis.com` แต่ไม่มีภาพหน้าจอหรือเอกสารประกอบมายืนยัน จึงไม่ควรถือว่าชื่อนี้ถูกต้องแน่นอน

รูปแบบคำสั่งทั่วไปคือ:

```bash
gcloud services enable SERVICE_NAME
```

ต้องแทน `SERVICE_NAME` ด้วยชื่อบริการจริงตามเอกสารของแพลตฟอร์มที่ใช้งาน และอาจต้องเปิด API อื่นเพิ่มเติมตามงานด้วย

### 21:49–23:03 — ตั้งค่าไฟล์ `.env`

ในโฟลเดอร์โปรเจกต์มีไฟล์สองชนิด:

| ไฟล์ | หน้าที่ |
| --- | --- |
| `.env.example` | แสดงตัวอย่างตัวแปรที่ต้องตั้งค่า |
| `.env` | เก็บค่าที่จะใช้จริงในการรันโปรเจกต์ |

ผู้บรรยายเลือกเชื่อมต่อผ่าน **Vertex AI** และใส่ Project ID ลงในไฟล์ `.env` อีกทางเลือกที่กล่าวถึงคือใช้ **Gemini API Key** จาก Google AI Studio

สองแนวทางนี้ใช้วิธียืนยันตัวตนและบริบทการคิดค่าบริการต่างกัน จึงต้องตั้งค่าให้ตรงกับแนวทางที่เลือก

ผู้บรรยายมีข้อกล่าวถึงการเติมเครดิตล่วงหน้าของ AI Studio แต่เงื่อนไขนี้อาจขึ้นกับบัญชีและช่วงเวลา จึงควรตรวจสอบเงื่อนไขปัจจุบันก่อนใช้งาน

ในข้อความที่ส่งมา **ไม่มีชื่อตัวแปรและค่าตั้งค่าทั้งหมดของ `.env`** จึงยังสร้างไฟล์ที่พร้อมคัดลอกไปใช้ให้ตรงกับโปรเจกต์นี้ไม่ได้ ต้องดู `.env.example` ที่ CLI สร้างมาประกอบ

### 23:04–24:09 — เปิด Playground และทดสอบ

ผู้บรรยายกลับไปที่ Terminal แล้วเปลี่ยนเข้าโฟลเดอร์ Agent จากนั้นเรียกคำสั่ง **Playground** ผ่าน Agents CLI

เครื่องมือเปิดหน้าเว็บทดสอบลักษณะ ADK Web โดยมีเซิร์ฟเวอร์ทำงานบน **localhost** หรือเครื่องของผู้พัฒนาเอง หน้าเว็บแสดงแอปชื่อ `app` ตามชื่อที่กำหนดไว้ก่อนหน้า

ข้อความทดสอบคือ:

> Hi, what's the weather like in San Francisco?

ลำดับการทำงานที่สาธิตคือ:

1. Agent รับคำถาม
2. โมเดลเลือกเรียกเครื่องมือสภาพอากาศ
3. เครื่องมือพบชื่อ San Francisco
4. เครื่องมือคืนค่าจำลอง 60°F และมีหมอก
5. Agent นำผลนั้นมาตอบผู้ใช้

การทดสอบนี้แสดงให้เห็นว่าเส้นทางพื้นฐานทำงานร่วมกันได้ ทั้งหน้าเว็บ Agent การเรียกโมเดล และการเรียกเครื่องมือ

**แม้หน้าเว็บและโค้ด Agent รันบนเครื่อง แต่การเรียกโมเดลยังเกิดผ่านบริการคลาวด์** จึงยังต้องมีอินเทอร์เน็ต ข้อมูลรับรอง และการตั้งค่าโครงการที่เหมาะสม

### 24:10–25:03 — ทบทวนสิ่งที่ทำสำเร็จ

เมื่อจบบท ผู้บรรยายมีระบบที่:

- เตรียมเครื่องมือพัฒนาพื้นฐานแล้ว
- มี Google Cloud Project และ Project ID
- ตั้งค่าการยืนยันตัวตนสำหรับแอปพลิเคชันแล้ว
- ตั้งค่า Project ใน CLI และในโปรเจกต์ Agent
- เปิด API ที่ใช้ในตัวอย่างแล้ว
- สร้างโครง Agent ผ่าน CLI
- เปิด Playground และทดสอบเรียกเครื่องมือได้

ผลลัพธ์ของบทนี้จึงเป็น **Agent เริ่มต้นที่รันและทดสอบบนเครื่องได้ โดยเชื่อมโมเดลผ่าน Google Cloud** ส่วนการ Deploy ขึ้นระบบจริงยังเป็นงานถัดไป

## สรุปท้ายเรื่อง

บทนี้พาจากการเตรียมเครื่องไปจนถึงการทดสอบ Agent ตัวแรก โดยมีลำดับหลักคือ:

**ติดตั้งเครื่องมือ → สร้าง Cloud Project → สร้างโครง Agent → ตั้งค่า ADC → ตั้งค่า `.env` และ API → เปิด Playground ทดสอบ**

| ประเด็น | ใจความ |
| --- | --- |
| **`agent.py`** | นิยามโมเดล คำสั่ง เครื่องมือ และ Root Agent |
| **`.env`** | เก็บค่าการเชื่อมต่อและสภาพแวดล้อม |
| **Root Agent** | จุดเริ่มต้นที่รับคำถามและเริ่มการทำงาน |
| **Docstring และ Type Hints** | ช่วยให้โมเดลเข้าใจวิธีเรียกเครื่องมือ |
| **ADC** | ข้อมูลรับรองให้โปรแกรมเรียก Google Cloud |
| **Project ID** | ต้องตั้งค่าให้สอดคล้องกันในส่วนที่เกี่ยวข้อง |
| **Playground** | หน้าเว็บสำหรับทดสอบ Agent บนเครื่อง |

ข้อจำกัดของตัวอย่างนี้คือ **Website Generator ยังเป็นเพียงชื่อโปรเจกต์** เครื่องมือสภาพอากาศใช้ข้อมูลจำลอง และยังไม่ได้ Deploy Agent ขึ้นคลาวด์

หากจะทำตามจริง จุดที่ต้องดูจากต้นฉบับหรือเอกสารเพิ่มคือ **Repository และคำสั่งติดตั้ง Agents CLI, Model ID, ชื่อ API ที่ต้องเปิด และตัวแปรใน `.env.example`** เพราะข้อความถอดเสียงยังให้รายละเอียดส่วนเหล่านี้ไม่ครบ
