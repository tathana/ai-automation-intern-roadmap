Evaluation · ประเมินผล

ตรวจพฤติกรรมตามเกณฑ์และข้อมูล เช่นเลือกเครื่องมือเหมาะหรือไม่ ต้องอ่านขอบเขตชุดทดสอบประกอบคะแนน

Pipeline · ขั้นตอนส่งเวอร์ชัน

กำหนดด่านตรวจและการเลื่อนไป staging/prod ช่วยรู้ว่าเวอร์ชันใดผ่านอะไรแล้วและหยุดรอผู้อนุมัติได้

Policy · กฎสิทธิ์

ควบคุมว่าจะให้ทำ action หรือไม่ตามบริบท ตัวอย่างคือห้าม issue_refund เมื่อยอดคำสั่งซื้อเกิน $100

Observability · หลักฐานระบบ

ใช้ log, trace และ metric ตามจากคำขอถึงผล แยก agent ตอบผิดออกจากเครื่องมือทำงานผิด

คำขอหนึ่งครั้งไหลอย่างไร

  1. ผู้ใช้ขอคืนเงิน
  2. Runtimeรับผ่าน endpoint
  3. Agentอ่านข้อมูล / เลือก tool
  4. Gateway / toolระบุ target
  5. Request interceptor*เติมยอดจากคำสั่งซื้อ
  6. Policy decision*ALLOW หรือ DENY
  7. Lambda refundไปต่อเฉพาะเมื่ออนุญาต
  8. คำตอบกลับผ่าน tool → agent

* ภาพเพื่อการเรียนรู้ตามเจตนาแล็บ ไม่ใช่ trace ที่ตรวจจริง หาก DENY ต้องหยุดก่อน Lambda refund แล้วส่งผลปฏิเสธกลับให้ agent อธิบายอย่างถูกต้อง

ทำไมลำดับ interceptor ↔ policy ต้องยืนยัน

เอกสาร AWS ตัวอย่างหนึ่งอธิบาย interceptor เติมข้อมูลก่อน Cedar แต่อีกบทความระบุ policy ก่อน interceptor จึงไม่ใช้ภาพนี้สรุปทุก configuration ให้ผู้สอนเทียบเอกสารรุ่นแล็บกับ trace จริง โดยเฉพาะ order_total_cents ถึงจุดตัดสินเมื่อใด

เอกสารต้นฉบับAWS · ตัวอย่าง interceptor ก่อน Cedar ↗AWS · อีก flow ที่ระบุ policy ก่อน interceptor ↗AWS · Gateway interceptors ↗
