เตรียมวันอังคาร · AWS AGENT WORKSHOP

เริ่มจากศูนย์: Mac, Terminal และ AWS CLI

ไม่ต้องจำทุกคำสั่ง เริ่มจากรู้ว่ากำลังพิมพ์ที่ไหน และคำสั่งนั้นทำอะไร

ขอบเขตหลักฐาน ผลทดลองอิงคำบอกเล่าของผู้ใช้จากภาพ ไม่ใช่การอ่าน AWS ล่าสุด เว็บไซต์ไม่มีการเชื่อมบัญชีหรือเรียก AWS

เริ่มจากตรงนี้: Mac ไม่ได้มี “ภาษา AWS” แยก

Mac เป็นเครื่องที่เราใช้ ส่วน Terminal คือหน้าต่างพิมพ์คำสั่ง และ shell เช่น zsh เป็นตัวอ่านคำสั่งนั้น AWS CLI คือโปรแกรมชื่อ aws ที่ติดตั้งเพิ่มหรือมีเตรียมไว้ในแล็บ ใช้สื่อสารกับบริการ AWS ได้ คำสั่ง AWS ส่วนใหญ่มีรูปแบบเดียวกันบน Mac กับ Linux แต่การต่อบรรทัดและตัวแปรอาจต่างจาก PowerShell

ไม่ต้องจำทุกคำสั่ง เป้าหมายแรกคือบอกได้ว่า “รันที่ไหน ใช้บัญชีไหน ทำอะไร และผลที่เห็นหมายถึงอะไร”

1 · ก่อนพิมพ์ ให้รู้ว่า Terminal อยู่ที่ไหน

Terminal บน Mac

Command+Space → พิมพ์ Terminal → Enter คำสั่งจัดไฟล์มีผลกับ Mac เครื่องนี้ AWS CLI อาจยังไม่ติดตั้งและยังไม่มีสิทธิ์เข้าแล็บ

Terminal ใน workshop

อาจเป็น editor บน browser, CloudShell หรือสภาพแวดล้อมที่ผู้สอนเตรียมให้ คำสั่งรันบนเครื่องฝั่งนั้น ไม่ใช่ Mac และอาจมีโปรแกรม/credentials เตรียมไว้แล้ว ต้องดูคำแนะนำของแล็บจริง

ถามก่อนเริ่ม: “คำสั่งชุดนี้ให้รันใน Terminal ของ workshop หรือบน Mac ครับ และแล็บเตรียม AWS CLI กับสิทธิ์ไว้ให้แล้วหรือยังครับ?”

การเปิด Console ผ่าน browser ไม่ได้ทำให้ Terminal บน Mac ล็อกอิน AWS ตามโดยอัตโนมัติ ตัวแปรที่ตั้งในหน้าต่างหนึ่งก็ไม่ได้ย้ายไปอีกเครื่อง

2 · แยกคำสั่งสามกลุ่ม

คำสั่ง shell / เครื่อง เช่น pwd, ls, cd
ใช้ดูหรือเปลี่ยนตำแหน่งไฟล์ ไม่ใช่บริการ AWS รันที่เครื่องใดก็ทำงานในบริบทของเครื่องนั้น
AWS CLI เช่น aws --version
เริ่มด้วยโปรแกรม aws ตามด้วยตัวเลือกหรือชื่อบริการ บางคำสั่งดูข้อมูลในเครื่อง บางคำสั่งติดต่อ AWS และบางคำสั่งเปลี่ยนทรัพยากร ต้องอ่านก่อนรัน
Python เช่น python script.py
เรียก interpreter ให้รันไฟล์ script.py ไฟล์นั้นอาจอ่านข้อมูลหรือเรียก cloud ผ่าน SDK ก็ได้ อย่าคิดว่าปลอดผลข้างเคียงเพราะไม่ได้ขึ้นต้น aws
agentcore กับ aws ไม่ใช่โปรแกรมเดียวกัน
คำสั่ง agentcore ในเอกสารบางชุดมาจากเครื่องมืออีกตัว รุ่นและรูปแบบอาจต่างกัน ใช้ตาม workshop ไม่สลับแทนคำสั่ง aws อัตโนมัติ

3 · ห้าคำสั่งแรก ไม่ต้องมีบัญชี AWS

Terminal · ดูตำแหน่ง
pwd

ผลเป็น path เช่น /Users/ชื่อผู้ใช้ บอก directory ปัจจุบัน ถ้าเป็นเครื่องแล็บ path อาจต่างไป

Terminal · ดูรายชื่อไฟล์
ls

ดูว่าไฟล์หรือโฟลเดอร์ที่บทเรียนอ้างถึงอยู่ตรงนี้หรือไม่ ผลว่างอาจแปลว่าโฟลเดอร์ไม่มีไฟล์ที่แสดง ไม่ใช่ AWS พัง

Terminal · กลับ home
cd ~

cd เปลี่ยน directory ส่วน ~ คือ home ของผู้ใช้ในเครื่องที่กำลังรัน ไม่จำเป็นต้องเป็น home บน Mac

Terminal · หา AWS CLI
command -v aws

แสดง path ถ้า shell หา aws พบ หากว่างแปลว่ายังหาไม่พบ อาจไม่ได้ติดตั้งหรือ PATH ยังไม่ถูก ไม่ได้บอกว่ามีสิทธิ์ AWS หรือไม่

Terminal · ดูรุ่น CLI
aws --version

ทำหลังหา aws พบ ควรเห็นข้อความ aws-cli/... การเห็นเวอร์ชันยืนยันแค่โปรแกรมทำงาน ไม่ยืนยันบัญชี region หรือ credentials

ถ้าเห็น % หรือ $ หน้าบรรทัดในเอกสาร นั่นมักเป็น prompt ไม่ต้องพิมพ์ตาม ตัวอย่างที่ปุ่มคัดลอกให้ไม่มี prompt นำหน้า

4 · อ่านคำสั่งเป็นชิ้น ไม่ต้องท่อง

โครงทั่วไปคือ aws → service → operation → options เช่นชื่อบริการ bedrock-agentcore-control และ operation get-agent-runtime-endpoint ใช้กับการดูรายละเอียด endpoint ตาม API ไม่ใช่การส่งข้อความให้ agent

aws
ชื่อโปรแกรมที่ shell จะเรียก
service
บริการที่จะทำงานด้วย เช่น sts, logs, codepipeline หรือ bedrock-agentcore-control
operation
สิ่งที่จะทำ เช่น get/list/describe โดยทั่วไปเป็นการอ่าน ส่วน create/update/delete/start ต้องตรวจผลกระทบ การ invoke agent ก็อาจทำให้ agent เรียก tool ที่เปลี่ยนข้อมูลได้
--region
เลือกภูมิภาคที่คำสั่งจะติดต่อ ต้องตรงกับแล็บ ไม่เดาจาก URL ที่เปิดบทเรียน
--profile
เลือกชุดการตั้งค่าที่มีอยู่ ไม่ใช่ชื่อ endpoint dev/staging/prod และไม่ได้สร้างสิทธิ์ขึ้นมาเอง
--output json
แสดงผลเป็น JSON คือข้อมูลแบบ key/value ที่โปรแกรมอ่านต่อได้
--query
เลือกหรือจัดรูปผลลัพธ์ด้วย JMESPath ไม่ใช่ SQL และไม่ใช่การแก้ข้อมูลต้นทาง
Terminal · อ่าน help ในเครื่อง
aws help

เปิดคำอธิบาย CLI ไม่เรียก API ของแล็บ ถ้าเข้าเครื่องมืออ่านหน้าข้อความ กด q เพื่อออก หาก help เปิดไม่ได้อาจขาดตัวแสดงคู่มือ ให้ดูเอกสารทางการแทน

Terminal · อ่าน help ของ operation
aws bedrock-agentcore-control get-agent-runtime-endpoint help

คำว่า help ท้ายบรรทัดทำให้เป็นการอ่านคู่มือ ไม่ใช่เรียกดู endpoint จริง ถ้า CLI ไม่รู้จัก service/operation ให้เทียบเวอร์ชันกับแล็บก่อนอัปเดตบนเครื่องบริษัท

หน้านี้ให้คัดลอกเฉพาะตัวอย่างที่ไม่เรียก AWS จริง เมื่อต้องอ่าน resource ของแล็บ ให้ใช้คำสั่งจาก workshop หลังตรวจบัญชี region และสิทธิ์กับผู้สอนแล้ว

5 · ตัวแปร $... คืออะไร

ตัวแปรคือชื่อที่ shell ใช้เก็บค่า เช่น NEW_VERSION เก็บหมายเลขเวอร์ชัน การเขียน $NEW_VERSION คือขอค่าที่เก็บไว้ ไม่ใช่ให้ AWS ค้นเวอร์ชันใหม่ให้ และเครื่องหมาย $ ในตำแหน่งนี้ไม่ใช่ prompt

Terminal · ทดลองตัวแปรสมมติ
DEMO_VERSION="example-only"
printf "Value: %s\n" "$DEMO_VERSION"

กำหนดค่าจำลองและแสดง Value: example-only ไม่ใช่หมายเลข Runtime จริง ตอนกำหนดค่าไม่มีช่องว่างข้าง = และตอนอ่านใช้ $

export
ทำให้โปรแกรมลูกที่เปิดจาก shell นี้เห็นตัวแปรด้วย ไม่ได้ส่งไปทุก Terminal หรือบันทึกถาวรอัตโนมัติ
เครื่องหมายคำพูด
Double quotes ให้ขยาย $ตัวแปร ส่วน single quotes เก็บข้อความตามตัวอักษร ครอบ path หรือค่าที่อาจมีช่องว่าง
backslash ที่ท้ายบรรทัด
ใน Bash/zsh ใช้ต่อคำสั่งหลายบรรทัด ต้องเป็นอักขระสุดท้าย ไม่เว้นช่องว่างหลังมัน หากยังไม่คล่องให้อ่านทั้งชุดก่อนวาง
$(...)
รันคำสั่งข้างในแล้วนำผลมาแทนที่ จึงไม่ใช่ข้อความเฉย ๆ อย่าวางโดยไม่อ่านสิ่งที่อยู่ข้างใน

ถ้า NEW_VERSION ว่าง อย่าใส่เลขเดา เปิด ตัวอย่างตรวจค่าว่าง แล้วตรวจค่าจากแล็บ ตัวแปรจำลองข้างบนใช้กับ pipeline จริงไม่ได้

6 · พื้นฐาน AWS ที่ต้องแยกให้ได้

Account · บัญชีทรัพยากร
ขอบเขตบัญชีที่ทรัพยากรและสิทธิ์อยู่ แล็บอาจให้บัญชีชั่วคราว ต้องรู้ว่าใช้ของแล็บ ไม่ใช่ของบริษัทหรือส่วนตัวโดยเผลอ
Region · ภูมิภาค
บริการและ resource จำนวนมากอยู่ตาม region หา resource ไม่เจออาจเป็นเพราะเลือกคนละ region ไม่ได้แปลว่าถูกลบ
IAM / role · ตัวตนและสิทธิ์
กำหนดว่าใครทำอะไรได้ การล็อกอินสำเร็จไม่แปลว่ามีสิทธิ์ทุก operation
Credentials · หลักฐานยืนยันตัวตน
อาจเป็นข้อมูลชั่วคราวจากแล็บหรือ SSO ตามทีม ไม่ใช่รหัสผ่านเว็บไซต์ที่นำไปใส่คำสั่งตรง ๆ ไม่แปะค่าเหล่านี้ในเว็บหรือแชต
Profile · ชุดตั้งค่า CLI
มีชื่อใช้เลือก configuration ในเครื่องนั้น การเลือก profile กับการเลือก endpoint prod เป็นคนละชั้น
ARN / resource ID
ARN เป็นรูปแบบอ้างอิงทรัพยากร ส่วน resource ID เป็นตัวระบุของบริการ อย่าใช้แทนกันโดยไม่ดู parameter และไม่ต้องนำค่าจริงมาใส่คู่มือนี้

ลำดับที่ควรรู้ก่อนเรียก API: เครื่องที่รัน → ตัวตน/บัญชี → region → resource → operation

7 · ต้องติดตั้งบน Mac ไหม?

ยังไม่จำเป็น ถ้า workshop มี Terminal พร้อมใช้และให้ทำในนั้น ใช้สภาพแวดล้อมที่ผู้สอนกำหนดก่อน ถ้าทีมให้ทำจาก Mac บริษัทจึงตรวจพอร์ทัลแอปหรือขอ IT ติดตั้ง AWS CLI v2 ตามช่องทางที่อนุญาต

  1. ตรวจ command -v aws กับ aws --version ก่อน ไม่ติดตั้งซ้ำโดยไม่รู้ของเดิม
  2. หากต้องติดตั้ง ใช้ installer macOS จากเอกสาร AWS ทางการตามสิทธิ์บริษัท ไม่ต้องติดตั้งผ่าน pip เพียงเพราะใช้ Python
  3. เปิด Terminal ใหม่และตรวจเวอร์ชันอีกครั้ง
  4. ตั้งการเข้าใช้งานตามวิธีแล็บ/ทีม เช่น IAM Identity Center หรือสิทธิ์ชั่วคราว อย่าสร้าง long-lived access key เองเพื่อแก้ปัญหา

aws configure sso และ aws sso login เป็นขั้นตอนตั้งค่า/เข้าสู่ระบบเมื่อทีมใช้ SSO และมีข้อมูลที่ถูกต้อง ไม่ใช่คำสั่งที่ทุกแล็บต้องรัน บางแล็บเตรียม role ไว้แล้วจึงใช้วิธีต่างกัน

8 · อ่าน JSON และ error ให้เป็น

JSON ใช้ปีกกาเก็บ object, ชื่อ field ในเครื่องหมายคำพูด และ : คั่นค่า เช่น {"status":"READY","amount_cents":25000} นี่เป็นตัวอย่างสมมติ ไม่ใช่ output API จริง ตัวเลข 25000 ต่างจากข้อความ "25000" โดยเฉพาะเวลาตรวจ type ใน policy

command not found: aws
shell หาโปรแกรมไม่พบ ตรวจการติดตั้ง/PATH ไม่ใช่แก้ IAM
Unable to locate credentials
CLI หา credentials ใช้งานไม่ได้ ตรวจวิธีเข้าสู่ระบบของแล็บ ไม่ใช่สร้าง key ใหม่ทันที
ExpiredToken / session หมดอายุ
ตรวจและต่ออายุผ่านวิธีที่ทีมกำหนด ไม่แก้ด้วยเปลี่ยน region สุ่ม
AccessDenied
การเรียกถูกปฏิเสธด้านสิทธิ์ ต้องดู identity/resource/action ไม่เติม sudo เพราะ sudo บน Mac ไม่เพิ่มสิทธิ์ AWS
ResourceNotFound
ตรวจบัญชี region และ ID ก่อนสรุปว่าทรัพยากรหาย
ValidationException
Input ไม่ผ่านเงื่อนไขที่บริการตรวจ ต้องอ่านข้อความส่วนที่ระบุ field เช่น invalid span(s) ไม่ได้หมายถึง agent สอบตก

9 · ลำดับอ่านสำหรับคนเริ่มจากศูนย์

  1. วันนี้: รู้ว่า Terminal ของ Mac กับของแล็บอยู่ที่ไหน
  2. ลอง pwd, ls และตัวแปรจำลองให้เข้าใจ
  3. ตรวจ aws --version และอ่าน help ในสภาพแวดล้อมที่ผู้สอนให้
  4. อ่านคำศัพท์ Account/Region/role แล้วไป Runtime, Gateway, policy และ span
  5. เล่น ห้องจำลอง แล้วค่อยเปิด checklist แก้เคส $250

ถ้าติดเรื่องแป้นพิมพ์หรือโฟลเดอร์ ให้เปิด Terminal บน Mac ตั้งแต่ศูนย์ และ คำสั่งจัดไฟล์ เพิ่มได้
