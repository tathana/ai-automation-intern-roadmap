20 — เตรียมโปรเจกต์ทีละขั้น: จากโฟลเดอร์ว่างจนพร้อมเขียน

หน้านี้รวมขั้นตอนที่ต้องพิมพ์เองไว้ใน Book 7 ทำตามจากบนลงล่างได้ ส่วนลิงก์ อ่านเพิ่ม ใช้เมื่อต้องการเข้าใจเรื่องนั้นลึกขึ้น ไม่ต้องอ่านครบทุกเล่มก่อนเริ่ม

ตัวอย่างใช้ Windows + PowerShell และ Python 3.11 ตามเครื่องที่ใช้ฝึก ชื่อโปรเจกต์คือ resume-evidence-assistant ถ้าทำบางขั้นแล้วให้ตรวจผลและข้ามไปขั้นถัดไป ไม่ต้องสร้างใหม่

สร้างโฟลเดอร์ → เปิด VS Code → ตรวจ Python/Git

      ↓
สร้าง README/.gitignore → เริ่ม Git → บันทึกจุดเริ่ม
      ↓
อ่าน Resume จาก TXT → PDF/DOCX → API → task → AI → review

1. สร้างโฟลเดอร์และเปิด Editor

เปิด PowerShell แล้วพิมพ์ทีละบรรทัด:

New-Item -ItemType Directory -Path D:\COOP\practice\resume-evidence-assistant -Force
Set-Location D:\COOP\practice\resume-evidence-assistant
code .
  • New-Item สร้างสิ่งใหม่ โดย -ItemType Directory ระบุว่าเป็นโฟลเดอร์
  • -Force ในคำสั่งสร้าง directory นี้ใช้กับโฟลเดอร์เดิมได้ ไม่ลบเนื้อหาข้างใน อย่าเหมารวมว่า Force ของทุกคำสั่งปลอดภัยเหมือนกัน
  • Set-Location เปลี่ยนตำแหน่งทำงานของ Terminal
  • code . เปิดโฟลเดอร์ปัจจุบันใน VS Code จุด . หมายถึงตำแหน่งที่อยู่ตอนนี้

ถ้าไม่มีไดรฟ์ D ให้เลือกโฟลเดอร์ของตัวเอง และใช้ path นั้นตลอดบท ถ้า code ไม่พบ ให้เปิด VS Code ด้วยตนเองแล้วเลือก File → Open Folder

2. ตรวจว่าพร้อมเริ่มหรือยัง

ใน VS Code เลือก Terminal → New Terminal และใช้ PowerShell สังเกต prompt ขึ้นต้น PS แล้วพิมพ์:

Get-Location
py --version
git --version

คำสั่งแรกบอกตำแหน่งทำงาน อีกสองคำสั่งตรวจว่าเรียกเครื่องมือได้ ตัวอย่างผลจากเครื่องฝึกคือ Python 3.11.9 และ Git 2.52.0 รุ่นไม่ต้องตรงทุกหลัก แต่เลือก Python ให้ตรงข้อกำหนดโปรเจกต์

ถ้า py ไม่พบแต่ python --version ใช้ได้ ให้ตรวจว่าเป็น Python รุ่นที่ต้องการก่อนใช้ python -m venv .venv แทน หากไม่มี Python/Git ให้ติดตั้งผ่านช่องทางที่เครื่องนั้นอนุญาตแล้วเปิด Terminal ใหม่

ตรวจผล: อยู่ในโฟลเดอร์โปรเจกต์ และคำสั่งทั้งสองแสดง version

อ่านเพิ่ม: Book 00 — Terminal และ Command

3. สร้าง Virtual Environment

Virtual environment คือพื้นที่แยก Python packages ของโปรเจกต์นี้ เพื่อไม่ให้การติดตั้ง package ของงานหนึ่งปะปนกับงานอื่น โฟลเดอร์นี้สร้างใหม่ได้จากรายการ dependencies จึงไม่ต้องเก็บใน Git

py -3.11 -m venv .venv

py -3.11 เลือก Python 3.11, -m venv เรียกโมดูลสร้าง environment และ .venv เป็นชื่อโฟลเดอร์ปลายทาง คำสั่งสำเร็จมักกลับมาที่ prompt โดยไม่มีข้อความพิเศษ

Python ที่ติดตั้งในเครื่อง
       ↓ สร้าง environment
project/.venv
       ├─ Python สำหรับเรียกใช้งาน
       └─ packages ของโปรเจกต์นี้

ตรวจผล: เห็นโฟลเดอร์ .venv ในโปรเจกต์ หากมีอยู่แล้วตรวจขั้นต่อไปก่อนสร้างทับ

อ่านเพิ่ม: Book 00 — Python, venv และ Dependencies

4. Activate และตรวจ Python ตัวที่ใช้อยู่

.\.venv\Scripts\Activate.ps1
python -c "import sys; print(sys.executable)"

Activate ปรับ environment ของ Terminal รอบนี้ให้ค้นหา Python ใน .venv ก่อน ไม่ได้เปลี่ยน Python ทั้งเครื่อง ส่วน -c ให้ Python รันโค้ดสั้นจากข้อความ sys.executable คือ path ของ Python ที่กำลังรันจริง

คาดหวังผล:

D:\COOP\practice\resume-evidence-assistant\.venv\Scripts\python.exe

มักเห็น (.venv) หน้า prompt ด้วย แต่ path ที่ตรวจได้เป็นหลักฐานที่ชัดกว่า เมื่อเปิด Terminal ใหม่ให้ activate ใหม่ แล้วเลือก Python: Select Interpreter จาก Command Palette ของ VS Code ให้ชี้ .venv เดียวกัน

เจอ error: running scripts is disabled on this system

ตัวอย่างเมื่อรัน .\.venv\Scripts\Activate.ps1 แล้ว PowerShell บล็อกสคริปต์ (path และการตัดบรรทัดอาจต่างกัน):

Activate.ps1 cannot be loaded because running scripts is disabled on this system.
CategoryInfo          : SecurityError: (:) [], PSSecurityException
FullyQualifiedErrorId : UnauthorizedAccess

ข้อความนี้หมายถึง Execution Policy ของ PowerShell ไม่อนุญาตให้รันสคริปต์ Activate ยังไม่ได้แปลว่า Python หรือ .venv เสีย และคำว่า UnauthorizedAccess ในกรณีนี้ไม่ได้หมายความว่าต้องเปิด Administrator เสมอไป

ให้เรียก Python ของโปรเจกต์โดยตรงก่อน:

.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"

ไม่จำเป็นต้องเปลี่ยน execution policy เพื่อทำขั้นนี้ หากใช้วิธีเรียกตรง คำสั่ง python ในขั้นต่อไปให้แทนด้วย .\.venv\Scripts\python.exe

ผลที่ควรเห็น: path ลงท้าย resume-evidence-assistant\.venv\Scripts\python.exe แม้ prompt ไม่มี (.venv) ก็ใช้ได้ เพราะเราระบุตัว Python ที่ต้องการแล้ว

Activate.ps1 ถูกบล็อก
       ↓
เรียก .venv\Scripts\python.exe โดยตรง
       ↓
ตรวจ sys.executable ชี้เข้าโปรเจกต์
       ↓
ใช้ Python ตัวนี้รันไฟล์และติดตั้ง package ต่อได้

ตัวอย่างสำหรับขั้นถัดไป รัน hello.py หลังสร้างไฟล์แล้ว และติดตั้ง pytest เมื่อถึงช่วงเขียน test:

.\.venv\Scripts\python.exe hello.py
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest --version

ระวัง path และ Python ของ Anaconda

พิมพ์ต้น path เป็น .\.venv โดยมี backslash คั่น:

.\       = เริ่มจากโฟลเดอร์ปัจจุบัน
.venv    = ชื่อโฟลเดอร์ environment
รวมกัน   = .\.venv\Scripts\python.exe

..venv ไม่มี backslash คั่น จึงเป็นคนละชื่อกับ .venv หากหา executable ไม่พบ ให้ตรวจตำแหน่งและไฟล์ก่อน:

Get-Location
Test-Path .\.venv\Scripts\python.exe

Test-Path ควรคืน True ถ้าเป็น False ให้ตรวจว่าอยู่ถูกโปรเจกต์และทำขั้นสร้าง .venv แล้ว อย่าเพิ่งสร้างทับหรือเปลี่ยนนโยบายเครื่อง

ถ้าพิมพ์ python เฉย ๆ แล้วยังได้ C:\Users\HP\anaconda3\python.exe แปลว่า Terminal ยังเลือก Anaconda จาก PATH ให้ใช้คำสั่งเรียกตรงด้านบน ไม่ต้องถอน Anaconda ส่วนปุ่ม Run ใน VS Code ให้เลือก interpreter ของ .venv ด้วย เพราะการเลือก interpreter ของ editor กับการ Activate ใน Terminal เป็นคนละส่วน

อ่านเพิ่ม: Book 00 — Environment และการเลือก executable

6. สร้างไฟล์บอกทางก่อนเก็บงานใน Git

สร้าง README.md ที่รากโปรเจกต์ แล้วเริ่มด้วย:

# Resume Evidence Assistant Lite

ช่วย HR อ่าน Resume สังเคราะห์และแสดงทักษะพร้อมหลักฐานให้คนตรวจ

## เป้าหมายแรก
อ่าน TXT ได้ก่อน แล้วเพิ่ม PDF/DOCX และ Mock AI

## Environment
Python 3.11, Windows PowerShell

## ทดลองรัน
python hello.py

สร้าง .gitignore ที่รากเดียวกันแล้วใส่:

.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.env

.gitignore บอก Git ว่าไฟล์ใหม่กลุ่มไหนไม่ต้องติดตาม ไม่ได้ทำให้ไฟล์ที่ commit ไปแล้วหายจากประวัติ ตัวอย่างนี้ไม่ ignore README, source และ test เพราะเป็นสิ่งที่คนอื่นต้องใช้

resume-evidence-assistant/
├─ .venv/       ← environment ไม่ commit
├─ .gitignore   ← กติกาไฟล์ที่ไม่ติดตาม
├─ README.md    ← วิธีเริ่มและรัน
└─ hello.py     ← ตรวจว่าเครื่องพร้อม

อ่านเพิ่ม: Git Special — Gitignore และ Secrets

7. เริ่ม Git และบันทึกจุดเริ่ม

ตรวจที่อยู่และ repository ก่อน:

Get-Location
git rev-parse --show-toplevel

ถ้าบอก not a git repository และอยู่ถูกโฟลเดอร์ ให้สร้าง repo:

git init -b main

ถ้าแสดง path โปรเจกต์นี้อยู่แล้วให้ข้าม init หากชี้ไปโฟลเดอร์แม่ แปลว่าอยู่ใน repo อื่น ให้แยกตำแหน่งโปรเจกต์ก่อน ไม่สร้าง repo ซ้อนโดยไม่ตั้งใจ

ตรวจผู้เขียน commit:

git config user.name
git config user.email

หากว่างหรือผิด ให้ตั้งเฉพาะ repo นี้ โดยแทนค่าตัวอย่างก่อนรัน:

git config user.name "YOUR NAME"
git config user.email "YOUR EMAIL"

ไม่ใช้ --global ในตัวอย่างนี้ จึงไม่เปลี่ยนผู้เขียนของงานอื่น ตรวจแล้วเก็บไฟล์ที่ทำเสร็จ:

git status
git add .gitignore README.md hello.py
git diff --cached
git commit -m "chore: initialize learning project"
git status

add เลือกไฟล์เข้าพื้นที่เตรียม commit หรือ staging; diff --cached ให้ตรวจสิ่งที่จะบันทึก; commit สร้างจุดบันทึกในเครื่อง ขั้นนี้ยังไม่ต้อง push ขึ้น GitHub

Checkpoint 7A — ตรวจ .gitignore ก่อน Stage

git status ควรเห็น .gitignore, README.md และ hello.py เป็น untracked แต่ไม่เห็น .venv จากนั้นถาม Git โดยตรงว่า path แต่ละแบบถูก ignore ด้วยกฎใด:

git check-ignore -v .venv
git check-ignore -v --no-index .env __pycache__/example.py .pytest_cache/example foo.pyc

-v หรือ verbose แสดงชื่อไฟล์ .gitignore, เลขบรรทัด, pattern และ path ที่ตรงกัน ส่วน --no-index ช่วยตรวจ pattern แม้ path ตัวอย่างยังไม่ได้ถูก track หรือยังไม่มีไฟล์จริง

ผลควรมีรูปแบบคล้าย:

.gitignore:1:.venv/          .venv
.gitignore:5:.env            .env
.gitignore:2:__pycache__/    __pycache__/example.py
.gitignore:4:.pytest_cache/  .pytest_cache/example
.gitignore:3:*.py[cod]       foo.pyc

หากคำสั่งไม่แสดง path ใด ให้กลับไปตรวจการสะกดและบรรทัดใน .gitignore ก่อน git add ข้อควรจำคือไฟล์ .gitignore เองต้องถูก commit เพื่อให้คนอื่นได้รับกติกาเดียวกัน

Checkpoint 7B — ตรวจ Git Identity

ชื่อและอีเมลจะถูกบันทึกใน metadata ของทุก commit ตรวจค่าที่ใช้กับ repository ปัจจุบัน:

git config user.name
git config user.email

หากต้องแก้เฉพาะโปรเจกต์นี้:

git config user.name "Thanaphat Chainarong"
git config user.email "thanaphatchainarong@gmail.com"

คำสั่งไม่มี --global จึงเขียนค่า local ใน .git/config และมีผลเฉพาะ repository นี้ เหมาะเมื่อ Repository บริษัทกับงานส่วนตัวใช้อีเมลต่างกัน

Checkpoint 7C — Stage แล้วอ่านสิ่งที่จะ Commit

git add .gitignore README.md hello.py
git status
git diff --cached

หลัง git add ไฟล์ควรอยู่ใต้ Changes to be committed คำสั่ง git diff --cached แสดงเนื้อหาจาก staging area ที่ commit ถัดไปกำลังจะบันทึก ให้ตรวจว่าไม่มี .env, secret, .venv หรือไฟล์ที่ไม่ได้ตั้งใจ

git diff ดูเหมือนค้างและขึ้น (END)

เมื่อผลลัพธ์ยาว Git อาจเปิดโปรแกรมแสดงข้อความทีละหน้าที่เรียกว่า pager โดย Git for Windows มักใช้โปรแกรม less ระหว่างนั้น PowerShell ไม่ได้ค้าง แต่กำลังรอคำสั่งจาก pager จึงยังไม่เห็น prompt PS ...>

หน้าจออาจลงท้ายแบบนี้:

\ No newline at end of file
(END)

(END) หมายถึงมาถึงท้าย diff แล้ว ส่วนเครื่องหมาย : ด้านล่างหมายถึง pager กำลังรอคำสั่ง กดปุ่มโดยไม่ต้องพิมพ์ต่อท้าย command:

ปุ่ม ผลใน pager
Space หรือ Page Down เลื่อนลงหนึ่งหน้า
ลูกศรขึ้น/ลง เลื่อนทีละบรรทัด
g ไปต้นผลลัพธ์
G ไปท้ายผลลัพธ์
/คำที่หา แล้ว Enter ค้นหาข้อความ
n ไปผลค้นหาถัดไป
q ออกจาก pager กลับ PowerShell 
git diff --cached
       ↓ ผลยาว
pager แสดงทีละหน้า
       ↓ กด q
กลับไปยัง PS ...> โดยไม่มีการแก้ไฟล์

ถ้ากด q แล้วไม่ออก ให้คลิกในพื้นที่ Terminal เพื่อให้ Terminal รับ keyboard focus แล้วกด q อีกครั้ง การออกจาก pager ไม่ยกเลิก staging และไม่ลบความเปลี่ยนแปลง

หากต้องการพิมพ์ผลทั้งหมดลง Terminal โดยไม่เปิด pager ใช้:

git --no-pager diff --cached

ตัวเลือก --no-pager มีผลกับคำสั่งครั้งนี้เท่านั้น เหมาะกับผลสั้นหรือเมื่อต้องการคัดลอก output แต่ผลยาวจะเลื่อนผ่านหน้าจอรวดเดียว

ข้อความ No newline at end of file เป็นข้อมูลใน diff ไม่ใช่คำสั่งของ pager หมายถึงไฟล์ไม่มีอักขระขึ้นบรรทัดใหม่หลังบรรทัดสุดท้าย เปิดไฟล์ กด Enter ที่ท้ายบรรทัด บันทึก แล้ว git add <file> ใหม่เพื่ออัปเดต staging ได้

Working directory
  ↓ git add เฉพาะไฟล์ที่ต้องการ
Staging area
  ↓ git diff --cached เพื่อตรวจ
Commit

ถ้า Stage ผิดไฟล์ ยังไม่ต้องลบไฟล์ ใช้ git restore --staged <file> นำไฟล์ออกจาก staging แล้วตรวจ git status ใหม่

ตรวจผล: commit สำเร็จ และ git status บอก working tree clean โดย .venv ไม่อยู่ในรายการที่จะ commit

อ่านเพิ่ม: Git Special — Setup และ First Repository, Staging และ Commit

8. Package ต้องติดตั้งตอนไหน

การอ่าน TXT ด้วย Python พื้นฐานยังไม่ต้องเพิ่ม package เมื่อเริ่มเขียน test ค่อยติดตั้ง pytest ใน .venv ที่ตรวจแล้ว:

python -m pip install pytest
python -m pytest --version

python -m pip ช่วยให้ติดตั้งผ่าน Python ตัวเดียวกับที่เราเลือกไว้ คำสั่งตรวจ version บอกเพียงว่ามี pytest ยังไม่ได้พิสูจน์ว่า test โปรเจกต์ผ่าน

บันทึก dependencies ที่ใช้จริงใน pyproject.toml หรือ requirements ตามรูปแบบที่เลือกให้ชัด และอ่านวิธีบันทึก version/lock ก่อนส่งมอบ เมื่อเพิ่ม PDF/DOCX จึงค่อยเพิ่ม reader dependencies

อ่านเพิ่ม: Book 00 — Dependency Declaration, Week 1 — Pytest

พร้อมไปเขียนฟังก์ชันแรกเมื่อใด

  • อยู่ในโฟลเดอร์ถูกต้องและเปิดด้วย VS Code
  • sys.executable ชี้ .venv ของโปรเจกต์
  • hello.py รันและแสดงข้อความได้
  • README ระบุเป้าหมายและวิธีรัน
  • Git เก็บจุดเริ่มแล้ว และไม่ติดตาม .venv หรือ .env
