ตรวจและส่งมอบก่อนใช้จริง

ไปที่ Prompt พร้อมใช้ ↓
จำแค่นี้

เดโมทำงานได้ คือจุดเริ่มของการตรวจ

1. Test2. Evaluate3. Review4. Approve5. Release6. Handoff

ทฤษฎีที่ใช้ทำงาน

Test สามระดับ

Unit ตรวจ logic เช่นสูตร Integration ตรวจส่วนเชื่อม End-to-end ตรวจทั้งเส้นทาง เลือกตามความเสี่ยง ไม่ทำเทสต์ที่เพียงคัดลอกสูตรจาก implementation

ชุดข้อมูลรู้คำตอบ

มี happy path, missing/invalid, duplicate, ขอบเขตวัน, upstream failure และ partial failure สำหรับ AI ต้องมี expected output หรือ rubric ที่ผู้ตรวจใช้ได้

วัด AI และระบบ

ดูความถูกต้องรายฟิลด์/หมวด อัตราส่งต่อคน เวลา และค่าใช้จ่าย เก็บ prompt/model/config version แยกชุดที่ใช้ปรับจากชุดตรวจสุดท้ายเพื่อลดการเข้ากับตัวอย่างเดิมอย่างเดียว

สิทธิ์และข้อมูลบริษัท

ถามเรื่องเครื่องมือ การติดตั้ง การเก็บข้อมูลและ retention ข้อมูลภายนอกอาจสั่งแทรก การจำกัด tool permissions และตรวจการกระทำต้องอยู่นอก prompt ด้วย

Release ตามขั้นตอนทีม

ให้ reviewer เห็นผลทดสอบ ข้อจำกัด config ปลายทาง งบ และวิธีปิดหรือ rollback ไม่เปิดการส่งจริงเพียงเพราะเดโมผ่าน

Handoff

README บอกเป้าหมาย ตั้งค่าโดยไม่มี secret วิธีรัน/ทดสอบ อาการผิดปกติ ผู้ดูแลและข้อจำกัด ให้คนรับช่วงลองตาม และบอกสิ่งที่ยังไม่ทดสอบตรง ๆ

อ่านรายละเอียดเฉพาะเครื่องมือ: Claude: เกณฑ์สำเร็จและการประเมิน

ก่อน–หลัง: ทำโจทย์ให้ตรวจได้

ยังคลุมเครือ

AI บอกผ่านแล้วส่งได้

ชัดขึ้น

เทียบผลรันกับเกณฑ์ แนบสิ่งที่ผ่านและยังไม่ทดสอบ ให้ reviewer ตรวจและอนุมัติขั้นใช้งาน

Prompt พร้อมปรับใช้

เติม [วงเล็บ] ด้วยบริบทที่อนุญาต เลือกใช้ภาษาไทยหรืออังกฤษตามทีม

Prompt ภาษาไทย

ตรวจ [ไฟล์และ requirement] ก่อนส่ง reviewer
จับคู่ acceptance criteria กับหลักฐาน
แยกผ่านจากการรันจริง / พบปัญหา / ยังไม่ทดสอบ
ตรวจข้อมูลขาด ซ้ำ เวลา error และผลข้างเคียงที่เกี่ยวข้อง
สรุปข้อจำกัด วิธีหยุด/กู้ และคู่มือส่งต่อ
อย่า deploy หรือส่งข้อมูลจริง
หากรันไม่ได้ให้เสนอวิธีตรวจแทนอ้างผล

Prompt English

Review [files and requirements] before handoff.
Map acceptance criteria to evidence.
Separate executed passes, failures, and untested cases.
Cover relevant missing/duplicate data, time boundaries, errors, and side effects.
Summarize limitations, stop/recovery steps, and handoff documentation.
Do not deploy or send live data.
If execution is unavailable, provide verification instructions instead of claiming results.

เมื่อเจอปัญหา

เคสใหม่ผิด

สาเหตุที่เป็นไปได้: ปรับตามตัวอย่างเดิมอย่างเดียว

ตรวจต่อ: ใช้ชุดตรวจที่ไม่ใช้ตอนปรับ

คนอื่นรันไม่ได้

สาเหตุที่เป็นไปได้: config อยู่ในเครื่องผู้ทำ

ตรวจต่อ: ให้ผู้รับลอง README ในระบบทดสอบ

ถามพี่อย่างไร

ก่อนใช้จริงต้องผ่าน review หรืออนุมัติใครบ้าง และใช้เกณฑ์อะไรครับ

ก่อนข้ามไปขั้นต่อไป

  • มีหลักฐานตามเกณฑ์
  • ระบุสิ่งไม่ทดสอบ
  • ไม่มี secret ในงานส่ง
  • มีเจ้าของและคู่มือ
